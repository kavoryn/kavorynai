System architecture — intended boundary

Conceptual architecture based on repository documentation; not a live deployment topology.

Android appKotlin · Compose · camera · sign-in · document UI
→
PHP APIAuth · consent · validation · orchestration · provider secrets
SupabaseAuth · private data · consent/audit · encrypted OCR results
External providersOpenAI · Gemini · OCR provider · TTS (subject to selection)

Client responsibilities

  • Capture/select and locally inspect documents.
  • Show what data will be sent and request explicit consent.
  • Present original OCR text separately from AI explanations.
  • Keep provider and service-role secrets out of the app.

Backend responsibilities

  • Verify user identity and ownership on every resource.
  • Validate consent, payload, limits and request idempotency.
  • Call only the explicitly selected AI provider.
  • Protect private data and clean temporary content on all paths.

Source documents: docs/ARCHITECTURE_DECISIONS.md, docs/BUILD_STATUS.md, docs/PRODUCT_REQUIREMENTS_V3.1.md.
